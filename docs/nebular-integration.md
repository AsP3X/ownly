# Nebular OS integration

← [Back to main README](../README.md) · [Documentation index](./README.md)

[Nebular OS](https://github.com/AsP3X/nebular-os) is Ownly’s object storage engine. In this monorepo it lives at `nebular-os/` as a **git submodule**.

## Vendor boundary

| Lives in Ownly | Lives in Nebular (upstream) |
|----------------|----------------------------|
| Compose wiring, env, public URL proxy | Blob store, zstd/NOSI, multipart, scrub |
| `files` metadata, quotas, placement | On-disk layout under `/data` |
| HLS encrypt + jobs | Serving GET/PUT of opaque objects |
| Upload sessions, dedup refcount | Optional block dedup (`NOS_DEDUP_*`) |

**Do not edit files under `nebular-os/` for Ownly features.** Storage engine changes belong in [AsP3X/nebular-os](https://github.com/AsP3X/nebular-os). Export local experimental diffs with:

```bash
./scripts/nebular-export-patch.sh
```

Git hooks (`./scripts/install-git-hooks.sh`) block accidental commits inside the submodule.

## Docker image

Compose builds the `object-storage` service from `nebular-os/` using [`docker/nebular-os.Dockerfile`](../docker/nebular-os.Dockerfile).

Data volume: `nebular_data` → container `/data` (`NOS_DATA_DIR=/data/blobs`, `NOS_META_PATH=/data/meta/metadata.db`).

Since Nebular OS 0.2 the server runs as the unprivileged user `nos` (uid/gid `10001`). The entrypoint starts as root only to hand `/data` to that user, then drops privileges. The Dockerfile strips CRLF from the upstream entrypoint so Windows checkouts (`core.autocrlf=true`) still build a working image.

## Nebular OS 0.2 settings

Ownly pins **v0.2.0**. Compose (`docker-compose.yml`, `docker-compose.rep.yml`) sets these on every node:

| Setting | Ownly default | Why |
|---------|---------------|-----|
| `NOS_JWT_ISSUER` / `NOS_JWT_AUDIENCE` | `ownly` / `nebular-os` (from `OBJECT_STORAGE_JWT_ISSUER` / `OBJECT_STORAGE_JWT_AUDIENCE`) | Nebular accepts only service JWTs minted for it, not any token signed with the same HS256 secret. The API adds the same `iss` / `aud`. |
| `NOS_METRICS_TOKEN` | generated by `init-env.sh` for new `.env` files | `/metrics` needs a bearer token; the API sends it for capacity probes. Empty leaves `/metrics` open. |
| `NOS_LEGACY_ACCESS_KEY_AUTH` | `false` | The old replayable `NOS <key>:<sig>` scheme stays off. |
| `NOS_ALLOW_PUBLIC_READ` | `false` | Every object read needs a JWT or a presigned URL. |
| `NOS_PRESIGN_MAX_TTL_SECS` | `86400` | Caps presigned URL lifetime. **Keep it ≥ `URL_EXPIRY_SECONDS`**, or download links are refused. |
| `NOS_CORS_ORIGINS` | `CORS_ALLOWED_ORIGINS` (any origin when that is empty) | Browsers reach Nebular same-origin via nginx `/media/`. Set in the base and replication files so overlay order can't reset it. |
| `NOS_FSYNC_WRITES` | `true` | A write is durable before it becomes visible. |
| `NOS_UPLOAD_IDLE_TIMEOUT_SECS` | `60` | Upload bodies that send nothing are cut off (`408`) and release the upload budget. |
| `NOS_HEADER_READ_TIMEOUT_SECS` | `75` | Slow-header / idle keep-alive connections are closed. The API's connection pool drops idle connections after 50 s, so it never reuses one Nebular just closed. |
| `NOS_SEND_STALL_TIMEOUT_SECS` | `300` | Downloads the client stopped reading free their buffers. |
| `NOS_SHUTDOWN_GRACE_SECS` | `8` (`stop_grace_period: 15s`) | Requests in progress finish on `docker stop`. |
| `NOS_BLOCK_CACHE_MAX_BYTES` | `64 MiB` | Byte budget for decoded compressed blocks. |
| `NOS_MAX_CONNECTIONS` | `0` (unlimited) | Optional cap on simultaneous connections. |
| `NOS_ORPHAN_GC_INTERVAL_SECS` | `0` | **Never enable with `NOS_METADATA_MODE=blob_only`**: orphan GC compares blobs with Nebular's own metadata, which that mode doesn't keep. |

`NOS_RATE_LIMIT_RPS` stays off: Nebular keys its limits on the peer IP, and every browser request arrives through the nginx container.

Buffered PUTs from the API (HLS segments, thumbnails, previews) send `Content-MD5`. Nebular checks it while the body streams and refuses a mismatch before anything is stored.

### Upgrading an existing deployment to 0.2

- **Back up `/data` first.** Once 0.2 has written or rewritten objects (new writes, recompression, `migrate_blobs`), rolling back to 0.1.4 serves wrong bytes.
- The first start hands a root-owned volume to `nos` with `chown -R`. On a large volume this can take minutes. It runs once, and a `.nos-owned` marker records it.
  - The healthcheck allows about 5 minutes (`start_period` 120 s + 18 × 10 s). If the ownership pass and index build take longer, `docker compose up` reports `object-storage` unhealthy and doesn't start the API. The container keeps working, so run `docker compose up -d` again once it is healthy.
  - To avoid that, hand the volume over before upgrading: `docker run --rm -v <project>_nebular_data:/data debian:bookworm-slim chown -R 10001:10001 /data`.
- The first start also builds a metadata index (about 0.7 s per million objects on SQLite).
- **Remote storage nodes** (registered in Admin → Storage Nodes and not started from this Compose project) must run 0.2 and set the same `NOS_JWT_ISSUER` / `NOS_JWT_AUDIENCE` as the API's `OBJECT_STORAGE_JWT_ISSUER` / `OBJECT_STORAGE_JWT_AUDIENCE`. Otherwise every request from the API gets `401`. If they set `NOS_METRICS_TOKEN`, it must match too. To turn the issuer/audience check off everywhere, set both `OBJECT_STORAGE_JWT_*` variables to empty in `.env`.
- At startup the API checks that the primary node accepts its service token and refuses to start with a message naming the settings to fix. Registered nodes are checked the first time the API uses them, and a refusal is logged as an error.
- Nebular's `POST /_nos/maintenance/migrate_blobs` has no dry-run mode. Ownly's admin migration with `dry_run=true` therefore only probes objects from the API side and never calls it.

## Bump the pinned commit

After an upstream release you want:

```bash
cd nebular-os && git fetch && git checkout <tag-or-sha>
cd .. && git add nebular-os
git commit -m "CHORE: Bump nebular-os to <tag-or-sha>"
```

Rebuild:

```bash
docker compose up --build object-storage
```

Then run Ownly's client against the running node (writes and deletes keys under `ownly-live-test/`):

```bash
cd backend
NEBULAR_LIVE_URL=http://127.0.0.1:9000 NOS_JWT_SECRET=… NOS_SIGNING_SECRET=… \
  OBJECT_STORAGE_JWT_ISSUER=ownly OBJECT_STORAGE_JWT_AUDIENCE=nebular-os \
  cargo test --test nebular_live -- --ignored --nocapture
```
